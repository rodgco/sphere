# 08 — Testing strategy

The layers below exist because the hard parts — hydration, attribution, base path, event
swallowing — cannot be proven in jsdom. Each layer answers a question the one above it cannot.

## 1. Layers

| Layer | What it proves | Tool |
|---|---|---|
| **Unit** | location algorithm, value summaries, prompt format, option handling, budgets | vitest, no DOM |
| **Golden** | the clipboard document is byte-stable | vitest + fixture + expected `.md` |
| **Runtime harness** | real compiled Svelte components through the wrapper: element → instance → props/state, multi-root templates, snippets | vitest project with the Svelte plugin and `dev: true` |
| **Browser e2e** | picking, event swallowing, marks, panel, clipboard, hydration, base path | Playwright against a real dev server |
| **Screenshots** | the UI is not broken, dark and light | Playwright + privacy scan |
| **Matrix** | supported Svelte/SvelteKit versions | CI jobs |

## 2. Unit

- Pure modules only (`format.ts`, `location.ts`, `budgets.ts`); no `document` access.
- The location algorithm has a case-per-row table (`docs/specs/location-resolution.md` §Test
  matrix) — every row is a test, named after the rule.
- Value formatting: inline budget boundaries (exactly at, one over), key quoting, nested limits,
  truncation markers, valid-JSON invariant for every runtime-produced value.
- Options: unknown keys rejected, defaults applied, `include` partial.

## 3. Runtime harness

- One vitest project of its own (`vitest.harness.config.ts`, `npm run test:harness`, also part of
  `npm test`); the unit project excludes `test/harness/**`.
- Wiring: the plugin plus `@sveltejs/vite-plugin-svelte` with `compilerOptions.dev: true`,
  `environment: 'happy-dom'`, `resolve.conditions: ['browser']`. Three facts make that work, all
  verified in `docs/learning/vitest-svelte-harness.md`: Vitest transforms test modules in a
  `client` environment (`ssr: false`), so `.svelte` files are compiled for the browser; the
  `browser` condition is what makes `mount()` come from `src/index-client.js`; and `unmount` is a
  free function, not a method on the mount result.
- Fixtures (`fixtures/harness/`): single root, multiple roots with a child component between them,
  `{#if}`, `{#each}`, a snippet rendered by a host, props with `$derived`, and a 500-entry
  `$state`.
- Baseline assertions (they must never break silently): every fixture renders, Svelte's
  `__svelte_meta.loc` points at the fixture file, and `svelte/internal/client` in the test graph is
  the generated wrapper (`isInstrumentationInstalled()`).
- `test/harness/instances.test.ts` asserts the instrumented model itself: element → instance name
  and file, the parent chain, the `component` usage frame (`line`, `componentTag`), attribution
  inside `{#if}`/`{#each}` including a branch rendered from an effect after init, live props, and
  named `$derived`/proxy state in creation order.
- `test/harness/inspect.test.ts` asserts the payload contract itself: identity without rendered
  text and without `svelte-` scopes, pessimistically-enclosing source, template frames, parseable
  `props`/`state` JSON for every fixture, the value budgets (`… N more`), `locateElement`, and
  “never throws” for `null`, a detached element and `document.body`.
- Delivery inside the harness: `test/harness/setup.ts` writes the wrapper generated by
  `wrapperModule()` to `test/harness/generated/`, and `test/harness/plugin.ts` resolves the client
  specifier to that file, applying the same “app modules only” rule. Vitest's client environment
  has no HTTP layer for `/@id/…`, so a `\0`-id cannot be loaded there; the real plumbing is
  covered against a dev server in `test/client-gate.test.ts`.
- `test/harness/panel.test.ts` drives the panel: opens on a pick with focus in the instructions,
  lists picks with number and label, removes and renumbers, reports the cap in words, keeps the
  instructions across close/open, Clear empties the form, the option toggles persist, and Escape
  closes the panel and returns focus to the control.
- `test/harness/overlay.test.ts` drives the control through native listeners: pointer up/down
  toggles, drag moves and persists without toggling, the 4 px threshold, double-click reset,
  Escape, and the cursor lock. `test/harness/entry.test.ts` asserts the shadow host, the styles
  and the single mount.
- **Known limit**: this harness mounts client-side; hydration behaviour cannot be tested here
  (vitest compiles a module for one target). Hydration belongs to the browser layer.

## 4. Browser e2e

One script per concern, each with its own dev server, one server at a time:

Delivery tests that need a real framework server (`test/kit-injection.test.ts`) spawn the fixture's
dev server on a free port, kill the process group in `afterAll`, and consume the **built** package
through a `file:` link. The fixture's dependencies are installed separately
(`npm --prefix fixtures/kit install`); locally a missing install skips, in CI it fails.

| Script | Cases |
|---|---|
| `e2e/picking.mjs` | pick a link (no navigation), leave picking (navigation works), unpick, cap message, marks follow scroll/resize |
| `e2e/location.mjs` | verified line (with column, no note), a corrupted `__svelte_meta.loc.line` forcing the matcher (note names the needle and the recorded ancestor, column dropped), an element stripped of identity so only the enclosing line is left, an `{@html}` element that inherits its host's location with the enclosing note, and `~` on the panel chip for approximate locations |
| `e2e/base-path.mjs` | `--base /app/`: overlay loads through the base, pick works, and the source window proves `/app/@fs/…?raw` answered (the base prefix is mandatory) |
| `e2e/a11y.mjs` | Enter/Space toggles, Escape leaves, focus returns, aria attributes present |
| `e2e/clipboard.mjs` | full flow with clipboard permissions; the pasted document has the header, both picks with the rule between them and the instructions; it contains no rendered text, no absolute path and no `node_modules`; the status line reports its size; Copy is disabled with nothing picked |

Shared plumbing (free port, process-group kill, browser context with clipboard permissions) lives
in `e2e/lib/`; the scripts stay readable and print one line on success. `fixtures/plain` exposes
bubble-phase counters on `window.__sphereTestCounters` — the only way to prove that a swallowed
event never reached the app and that a passed-through one did.

## 5. Screenshots

- `scripts/screenshots/sphere.mjs` boots the example app, picks two elements, opens the panel,
  captures dark and light, writes a manifest (commit, runner, viewport, per-shot result).
- Privacy scan before writing: the visible text — text nodes and the attributes that render as
  text, **shadow roots included** — must not match machine paths (`/home/`, `/Users/`, the runner's
  home) or token patterns. A hit fails the case and writes no image. Svelte's dev `<style>` carries
  an absolute filename in an attribute; that is dev-server plumbing the image cannot show, so the
  scan looks at what a reader can see, not at every attribute.
- Images are committed under `docs/images/` and referenced from the README. CI runs the script on
  every push: privacy failures fail the build, and the regenerated images are the artifact under
  review. Pixel diffing is deliberately **not** a CI gate — font rendering differs between the
  runner and a developer machine, so a pixel gate would fail for reasons unrelated to Sphere.

## 6. Version matrix (CI)

| Job | Content | Status |
|---|---|---|
| `check` (main) | lint, format, typecheck, build, `publint` + `attw`, unit + runtime harness, SvelteKit 3 fixture, all five browser scripts | implemented |
| `svelte-minors` | the harness against the last four Svelte minors; the instrumentation is what can silently mis-attribute | implemented |
| `plain-vite` | plain Svelte + Vite, browser scripts | inside `check` (`fixtures/plain`) |
| `prod-noop` | build the fixture and fail if the output mentions Sphere | inside `check` (`test/prod-noop.test.ts`) |
| `kit` | SvelteKit 2 **and** 3 apps, location + base path | Kit 3 implemented; a real Kit 2 app is still a manual run (the transform is unit-tested) |
| `bundle-size` | the plugin's Node entry stays under a declared budget | not implemented |

## 7. Coverage and lint policy

- Coverage thresholds are global and per critical module (`location`, `format`): ≥ 95 % branches,
  ≥ 98 % lines. The overlay is excluded from coverage **only** if it is Svelte-only and covered by
  e2e; the exclusion must carry that sentence as its justification.
- Lint/format/typecheck are blockers (`oxlint`, `oxfmt`, `tsc --noEmit`, `svelte-check` for the
  overlay; `npm run typecheck` runs both).
- No test may assert wall-clock timings; performance lives in `perf/` and is reported, not gated.

## 8. Flakiness rules

- No `sleep` in unit tests; in e2e only to let an animation settle, never to wait for a state —
  wait for the state.
- Clipboard reads are retried once with a fresh permission grant.
- A test that needs a dev server gets its own port and its own `HOME`; a leaked server fails the
  next run, so the harness kills the process group in `finally`.
