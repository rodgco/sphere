# 08 — Testing strategy

The prototype's test suite is the template: it is the reason the hard parts (hydration,
attribution, base path) are known-good. Sphere keeps the same layers and adds the ones the
prototype deferred.

## 1. Layers

| Layer | What it proves | Tool |
|---|---|---|
| **Unit** | location algorithm, value summaries, prompt format, option handling, budgets | vitest, no DOM |
| **Golden** | the clipboard document is byte-stable | vitest + fixture + expected `.md` |
| **Runtime harness** | real compiled Svelte components through the wrapper: element → instance → props/state, multi-root templates, snippets | vitest project with the Svelte plugin and `dev: true` |
| **Browser e2e** | picking, event swallowing, marks, panel, clipboard, hydration, base path | Playwright against a real dev server |
| **Screenshots** | the UI is not broken, dark and light | Playwright + privacy scan |
| **Matrix** | supported Svelte/SvelteKit versions | CI jobs |

## 2. Unit

- Pure modules only (`format.ts`, `location.ts`, `budgets.ts`); no `document` access.
- The location algorithm has a case-per-row table (`docs/specs/location-resolution.md` §Test
  matrix) — every row is a test, named after the rule.
- Value formatting: inline budget boundaries (exactly at, one over), key quoting, nested limits,
  truncation markers, valid-JSON invariant for every runtime-produced value.
- Options: unknown keys rejected, defaults applied, `include` partial.

## 3. Runtime harness

- A vitest project that compiles fixtures with the Svelte plugin (`dev: true`) and loads the
  wrapper as the client module — the same wiring the dev server uses, no browser.
- Fixtures cover: single root, multiple roots with a child component between them, `{#if}` /
  `{#each}` blocks, snippets (`{@render children()}`), a component with props and derived state,
  a component with a large state value.
- Assertions: `components[0].name`, `usage.line`, `source.line`, `props`, `state` values, and
  "no text in markup".
- **Known limit**: this harness mounts client-side; hydration behaviour cannot be tested here
  (vitest compiles a module for one target). Hydration belongs to the browser layer.

## 4. Browser e2e

One script per concern, each with its own dev server, one server at a time:

| Script | Cases |
|---|---|
| `e2e/picking.mjs` | pick a link (no navigation), leave picking (navigation works), unpick, cap message, marks follow scroll/resize |
| `e2e/location.mjs` | chip line equals the line read from disk; `~` when metadata is dropped; note text present |
| `e2e/base-path.mjs` | `paths.base: '/app'` profile: overlay loads, pick works, source window fetched through the base |
| `e2e/a11y.mjs` | Enter/Space toggles, Escape leaves, focus returns, aria attributes present |
| `e2e/clipboard.mjs` | full flow with clipboard permissions; payload contains no absolute path and no rendered text |

Shared plumbing (spawn dev server with isolated `HOME`, free port, process-group kill, browser
context with clipboard permissions) lives in `e2e/lib/`; the scripts stay readable.

## 5. Screenshots

- `scripts/screenshots/sphere.mjs` boots the example app, picks two elements, opens the panel,
  captures dark and light, writes a manifest (commit, runner, viewport, per-shot result).
- Privacy scan before writing: the visible text — **shadow roots included** — must not match
  machine paths (`/home/`, `/Users/`, the runner's home), tokens, or the devtools one-time code.
  A hit fails the case and writes no image.
- Images are committed under `docs/images/`, referenced from the README, and regenerated by a CI
  job so they cannot go stale silently.

## 6. Version matrix (CI)

| Job | Content |
|---|---|
| `svelte-minors` | latest 5.x plus two previous minors, runtime harness + e2e picking (fails loud if `svelte/internal/client` changed) |
| `kit` | SvelteKit 2 and 3 example apps, e2e location + base path |
| `plain-vite` | plain Svelte + Vite app, e2e picking (no Kit) |
| `prod-noop` | build a fixture and grep for `sphere` / `virtual:sphere` in the output |
| `bundle-size` | the plugin's Node entry stays under a declared budget |

## 7. Coverage and lint policy

- Coverage thresholds are global and per critical module (`location`, `format`): ≥ 95 % branches,
  ≥ 98 % lines. The overlay is excluded from coverage **only** if it is Svelte-only and covered by
  e2e; the exclusion must carry that sentence as its justification.
- Lint/format/typecheck are blockers (`oxlint`/`eslint` per the repo's choice, `oxfmt`,
  `tsc --noEmit`, `svelte-check`).
- No test may assert wall-clock timings; performance lives in `perf/` and is reported, not gated.

## 8. Flakiness rules

- No `sleep` in unit tests; in e2e only to let an animation settle, never to wait for a state —
  wait for the state.
- Clipboard reads are retried once with a fresh permission grant.
- A test that needs a dev server gets its own port and its own `HOME`; a leaked server fails the
  next run, so the harness kills the process group in `finally`.
